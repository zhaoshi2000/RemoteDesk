# 安全边界与发布限制

本交付没有通过第三方安全审计，不应以“生产级远控已完成”的名义部署给不知情用户。只用于明确授权的设备和隔离验证环境。

## 实际信任模型

服务端 enrollment token 只允许注册设备，admin token 只读取后台。注册设备不等于授权控制其他设备。每台 Agent 本地 trusted.json 固定允许的公钥和能力，首次为空。

服务端使用自己的 HTTPS 证书；设备间另外建立 TLS 1.3 双向认证。peer TLS 不使用公网域名 CA 作为设备身份根，而是严格比较本地授权公钥，并验证证书自签名、有效期、ALPN，以及 TLS 的私钥持有证明。代码里 `InsecureSkipVerify: true` **仅在这一个自定义设备 pinning 场景使用**，同时强制 `VerifyConnection`；控制面 HTTPS 没有忽略证书的选项。

服务器即使掌握某个中继票据，也没有对应被授权设备的私钥，因此不能凭票据进入目标 SSH。服务器仍然能拒绝服务、阻断信令、观察设备/IP/时序/流量大小；“端到端加密”不等于隐藏所有元数据。

SSH 的 Windows 用户认证和主机密钥验证仍然独立存在。使用 OpenSSH 既有账号/公钥，不创建通用默认账号、空密码或共享 root/admin 密码。

## 密钥与文件

Windows 采用 DPAPI machine 保护，并设置专属目录 DACL。Machine DPAPI 单独不足以隔离本机用户，因此必须保留限制性的文件 ACL。本机管理员/SYSTEM 被视为可信主机管理者。服务安装脚本另将程序复制到 Program Files 下的受保护 ServiceBin，只允许管理员/SYSTEM 写入，避免从普通用户可写的路径启动 LocalSystem 服务；此安装代码仍待 Windows 实测。

Linux 的测试/连接工具使用 0700 目录、0600 私钥，不声称具有硬件密钥保护。配置和密钥都不可放到网络共享目录。初始化拒绝覆盖现有密钥，新的 state 目录必须为空。

共享的服务器注册令牌尚未细化为每次安装的一次性 enrollment token；管理员应限制发放范围并在部署批次后轮换。当前生产账户系统/MFA、PAKE/验证码、密钥轮换未实现。

## 协议约束

请求签名覆盖方法、URI、正文 SHA-256、时间戳、随机数和设备公钥；窗口为 ±60 秒，防重放保留两倍窗口。候选和连接 intent 另行签名，服务器不能悄悄替换 TCP 目标地址为无签名内容。

STUN 只做 IPv4 Binding 子集。STUN 发现本身不是设备身份验证，也不是完整 NAT 穿透方案。打洞探测只接受本地授权、公钥签名、匹配 session/nonce 的数据；不接受任意 UDP 执行命令。

本地 SSH 转发监听只允许 loopback。远端没有“任意目标 host:port”参数，只能连接被控机自己配置的回环 SSH 端口。

服务端中继票据有效 40 秒，一次使用，双侧单独票据；配对后连接上限 1 小时，每方向最多 1 GiB。当前不提供持续 SSH 会话迁移或跨服务器恢复。

公网 DDoS/全局 UDP 流量限制、分布式持久防重放、细粒度设备/用户/租户权限、活动会话即时撤销、设备注销/密钥轮换、可靠审计日志/轮转、管理员登录与 MFA、签名更新、版本回滚、OpenSSH/Windows 安装链路实机验证、协议模糊测试长期运行、真实 NAT/弱网压力测试仍待完成。

Go 工具链版本是构建环境现有的 1.23.2；没有宣称它是当前安全版本。发布前须以受支持版本重编译和漏洞扫描。`go test -race`、单元测试与短时 fuzz 只能证明它们覆盖的测试没有失败，不能代替全面审计。
