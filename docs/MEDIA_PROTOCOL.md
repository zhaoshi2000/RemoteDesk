# 媒体接口增量（尚未接入网络）

`internal/protocol/media.go` 的包头只用于未来**已经认证和加密的 QUIC DATAGRAM 内部**。不要把它直接当成裸 UDP 视频加密协议。

| 字节偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 4 | ASCII RDM1 |
| 4 | 1 | 版本 1 |
| 5 | 1 | Channel 0..7 |
| 6 | 1 | Flags，仅位 0/1 保留为关键帧/配置标记 |
| 7 | 1 | 保留，必须为 0 |
| 8 | 4 | Frame ID，大端 |
| 12 | 2 | Fragment index，大端，从 0 开始 |
| 14 | 2 | Fragment count，大端，1..4096 |
| 16 | 8 | 发送端单调时间戳微秒，大端 |
| 24 | 2 | Payload length，大端，最大 1150 |
| 26 | N | Payload |

包头不提供加密、重组、FEC、重传或拥塞控制；这些不能被误认为已经实现。SSH/键盘/文件等必须按可靠通道语义使用，不能因为有 channel 编号就直接放进不可靠 DATAGRAM。

Golden vector：`52444d3101030100010203040001000201020304050607080002aabb`。

`native/core/realtime.hpp` 提供有界队列和独立码率决策。鼠标位置可合并，键盘/按钮不允许按位置通道合并；文件/视频为低优先级，预留高优先级容量。可靠数据 enqueue 返回 false 时必须背压或显式中断，不允许静默丢弃。

队列和 bitrate 决策尚未绑定真实传输/编码器；它们通过单元测试不代表“文件下载时远控绝对不卡”。实际 QUIC 连接的拥塞预算、pacing、重传与后台文件带宽上限仍需联调。
